
# UX Specification — Start & Character Creation Entry Flow

## 1. Назначение

Документ описывает начальный пользовательский сценарий **Character Manager**:

1. вход пользователя в приложение;
    
2. выбор действия на стартовой странице;
    
3. начало создания нового персонажа;
    
4. выбор игровой системы.
    

Документ описывает только пользовательский опыт и поведение интерфейса.

---

## 2. Цель пользователя

После открытия Character Manager пользователь должен сразу понимать, какие основные действия ему доступны.

На стартовой странице пользователь может:

- **создать нового персонажа**;
    
- **загрузить существующего персонажа**.
    

В рамках MVP основным рабочим сценарием является **создание нового персонажа**.

---

# 3. Общий User Flow

```
Стартовая страница
        │
        ├── Создать нового персонажа
        │           │
        │           ▼
        │    Выбор игровой системы
        │           │
        │           ├── Pathfinder 2e
        │           │        │
        │           │        ▼
        │           │   Создание персонажа PF2e
        │           │
        │           └── D&D 5e (2014)
        │                    │
        │                    ▼
        │             Создание персонажа D&D
        │
        └── Загрузить персонажа
                    │
                    ▼
             Не входит в MVP
```

---

# 4. Стартовая страница

## Назначение

Стартовая страница является первой точкой взаимодействия пользователя с Character Manager.

Она должна максимально быстро отвечать на вопрос:

> **Что я хочу сделать со своим персонажем?**

---

## Основные действия

Пользователю доступны два сценария.

### Создать нового персонажа

Основное действие стартовой страницы.

Пользователь начинает процесс создания нового героя с нуля.

Действие должно визуально иметь больший приоритет относительно остальных элементов страницы.

---

### Загрузить персонажа

Позволяет пользователю загрузить ранее созданного или полученного персонажа.

Функциональность **не входит в MVP**.

На этапе MVP действие может отображаться как недоступное с обозначением:

> **Скоро**

или

> **Coming soon**

Таким образом пользователь понимает, что возможность предусмотрена продуктом, но пока недоступна.

---

# 5. Создание нового персонажа

## Точка входа

Пользователь выбирает:

> **Создать нового персонажа**

После этого он переходит к выбору игровой системы.

Никакие дополнительные настройки до выбора системы пользователю не предлагаются.

---

# 6. Выбор игровой системы

## Назначение

Игровая система определяет дальнейший процесс создания персонажа.

Пользователь должен выбрать систему, для которой он хочет создать героя.

---

## Доступные системы в MVP

### Pathfinder 2e

Отображаемое название:

> **Pathfinder 2e**

Допустимое сокращение:

> **PF2e**

Выбор запускает процесс создания персонажа для Pathfinder 2e.

---

### Dungeons & Dragons 5e

Отображаемое название:

> **Dungeons & Dragons 5e**

Редакция должна быть явно обозначена:

> **2014**

Например:

> **Dungeons & Dragons 5e · 2014**

или

> **D&D 5e (2014)**

Это необходимо, чтобы в будущем можно было однозначно отличать её от других редакций D&D.

---

# 7. Представление игровых систем

Каждая игровая система представляется как самостоятельный визуальный элемент.

Карточка системы должна позволять пользователю быстро определить:

- название системы;
    
- редакцию;
    
- принадлежность к конкретной НРИ;
    
- возможность начать создание персонажа.
    

В MVP отображаются две карточки:

```
┌─────────────────────────┐
│                         │
│      Pathfinder 2e      │
│                         │
│          PF2e           │
│                         │
│   Создать персонажа →   │
│                         │
└─────────────────────────┘


┌─────────────────────────┐
│                         │
│   Dungeons & Dragons    │
│                         │
│       5e · 2014         │
│                         │
│   Создать персонажа →   │
│                         │
└─────────────────────────┘
```

Карточки должны восприниматься как равнозначные варианты выбора.

---

# 8. Выбор системы

После выбора игровой системы пользователь сразу переходит к процессу создания персонажа соответствующей системы.

Дополнительное подтверждение выбора не требуется.

```
Pathfinder 2e
      │
      ▼
Создание персонажа PF2e
```

```
D&D 5e · 2014
      │
      ▼
Создание персонажа D&D
```

---

# 9. Возврат назад

На странице выбора игровой системы пользователь должен иметь возможность вернуться на стартовую страницу.

При возврате никакие данные не теряются, поскольку процесс создания персонажа ещё не начался.

---

# 10. Основной сценарий

### Шаг 1

Пользователь открывает Character Manager.

### Шаг 2

Пользователь видит два основных действия:

- создать нового персонажа;
    
- загрузить персонажа.
    

### Шаг 3

Пользователь выбирает **«Создать нового персонажа»**.

### Шаг 4

Открывается экран выбора игровой системы.

### Шаг 5

Пользователь выбирает:

- Pathfinder 2e;
    

или

- Dungeons & Dragons 5e (2014).
    

### Шаг 6

Пользователь переходит к процессу создания персонажа выбранной системы.

---

# 11. MVP Scope

В рамках данного flow в MVP входят:

- стартовая страница;
    
- действие **«Создать нового персонажа»**;
    
- экран выбора игровой системы;
    
- выбор **Pathfinder 2e**;
    
- выбор **Dungeons & Dragons 5e (2014)**;
    
- переход к соответствующему процессу создания персонажа.
    

---

## Не входит в MVP

На текущем этапе не рассматриваются:

- загрузка существующего персонажа;
    
- импорт персонажа из сторонних сервисов;
    
- дополнительные игровые системы;
    
- поиск игровых систем;
    
- фильтрация игровых систем;
    
- избранные системы;
    
- недавние персонажи;
    
- аккаунт пользователя;
    
- облачная синхронизация.
    

---

# 12. UX-принципы

### Минимальное количество действий

Пользователь должен начать создание персонажа за минимальное количество шагов:

```
Старт
  ↓
Создать персонажа
  ↓
Выбрать систему
  ↓
Character Builder
```

### Один экран — одно основное решение

Стартовая страница отвечает на вопрос:

> Что пользователь хочет сделать?

Экран выбора системы отвечает на вопрос:

> Для какой игровой системы пользователь создаёт персонажа?

Эти решения не должны смешиваться на одном экране.

### Масштабируемость

Интерфейс выбора системы должен предусматривать возможность добавления новых игровых систем и редакций в будущем.

Например:

```
Pathfinder 2e
D&D 5e · 2014
D&D 5e · 2024
Pathfinder 1e
...
```

Добавление новых систем не должно менять основной пользовательский flow.
